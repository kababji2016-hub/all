# النظام الشامل

نظام واحد مستقل يجمع كل الأنظمة (الخزينة، الرواتب، الوثائق والمهام، يوميات الفروع)
بتسجيل دخول موحّد وقاعدة بيانات واحدة جديدة، ويسمح بإضافة أي نظام جديد بسهولة.

> الأنظمة القديمة (ERADAT / Rawateb / TNBEHAT KABABJE) لم تُمس — هذا المجلد مستقل تماماً عنها.

---

## البنية

```
all/
├─ firebase.json            إعدادات الاستضافة والقواعد
├─ .firebaserc              معرّف مشروع Firebase الجديد
├─ firestore.rules          قواعد الحماية (حسب بادئة اسم المجموعة)
├─ deploy.ps1               النشر بأمر واحد
├─ public/
│  ├─ index.html            الواجهة الرئيسية: الدخول، قائمة الأنظمة، المستخدمون والصلاحيات
│  ├─ core/
│  │  ├─ firebase-config.js إعدادات مشروع Firebase الجديد  ← تعدّله مرة واحدة
│  │  ├─ modules.js         سجل الأنظمة                    ← تضيف فيه أي نظام جديد
│  │  └─ core.js            النواة المشتركة (AllCore)
│  └─ modules/
│     ├─ finance/           نظام الخزينة       (منسوخ من ERADAT)
│     ├─ payroll/           نظام الرواتب       (منسوخ من Rawateb)
│     ├─ docs/              الوثائق والمهام    (منسوخ من TNBEHAT KABABJE)
│     ├─ journal/           يوميات الفروع      (منسوخ من Rawateb/public/daily-journal.html)
│     └─ _template/         قالب لأي نظام جديد
└─ tools/notifier/          برنامج تنبيه ويندوز (يقرأ من قاعدة البيانات الجديدة)
```

كل نظام يعمل داخل الواجهة الرئيسية (في إطار مستقل، فيحتفظ بشكله وحالته عند التنقل بين الأنظمة)،
ويمكن فتحه أيضاً مباشرة في صفحة مستقلة (`/finance`، `/payroll`، `/docs`، `/journal`).

---

## الإعداد لأول مرة

1. **إنشاء مشروع Firebase جديد** من [console.firebase.google.com](https://console.firebase.google.com).
2. **Authentication** ← Get started ← Sign-in method ← فعّل **Email/Password**.
3. **Firestore Database** ← Create database (production mode).
4. **Project settings** ← Your apps ← أضف تطبيق **Web** ← انسخ القيم إلى
   `public/core/firebase-config.js` بدل `PUT_...`.
5. ضع معرّف المشروع في `.firebaserc` بدل `PUT_PROJECT_ID`.
6. من داخل مجلد `all`:
   ```powershell
   firebase login
   .\deploy.ps1
   ```
7. افتح رابط الموقع ← تظهر شاشة **إعداد النظام لأول مرة** ← أنشئ حساب مدير النظام.
8. من **المستخدمون والصلاحيات** أضف باقي المستخدمين وحدد الأنظمة المسموحة لكل واحد.

للتجربة على جهازك قبل النشر: `firebase serve --only hosting` ثم افتح `http://localhost:5000`
(يحتاج أن تكون الخطوات 1–5 منفّذة والقواعد منشورة).

## المستخدمون والصلاحيات

- **مدير النظام**: يدخل كل الأنظمة بصلاحية كاملة ويدير المستخدمين والإعدادات.
- **مستخدم**: يدخل فقط الأنظمة المحددة له. بعض الأنظمة لها أدوار داخلية
  (الخزينة: موظف / مسؤول الخزينة).
- اسم المستخدم يمكن أن يكون عربياً. داخلياً يُحوَّل إلى بريد ثابت لأن Firebase يتطلب بريداً.
- إيقاف الحساب يمنع الدخول فوراً لكل الأنظمة.
- كل مستخدم يغيّر كلمة مروره من **حسابي**.
  ⚠️ لا يستطيع المدير تغيير كلمة مرور مستخدم آخر من المتصفح (قيد في Firebase بدون خادم):
  الحل الحالي أن يوقف الحساب وينشئ حساباً جديداً.

## قاعدة البيانات

كل نظام يملك مجموعاته الخاصة، وكل اسم مجموعة يبدأ بمعرّف النظام:

| النظام | المجموعات |
|---|---|
| النواة | `core_users`, `core_settings`, `core_meta` |
| الخزينة `finance` | `finance_config`, `finance_entries`, `finance_logs` |
| الرواتب `payroll` | `payroll_employees`, `payroll_loans`, `payroll_deductions`, `payroll_branches`, `payroll_settings`, `payroll_deliveries`, `payroll_history_details`, `payroll_sheets` |
| الوثائق `docs` | `docs_documents`, `docs_tasks`, `docs_tasks_done`, `docs_settings` |
| اليوميات `journal` | `journal_entries`, `journal_settings` |

**قاعدة الحماية:** المستخدم يصل إلى `<id>_*` فقط إن كان النظام `<id>` من الأنظمة المسموحة له.
لذلك أي نظام جديد يلتزم بالبادئة يصبح محمياً تلقائياً دون تعديل `firestore.rules`.

## إضافة نظام جديد

1. انسخ `public/modules/_template` إلى `public/modules/<id>` (مثلاً `inventory`).
2. في الملف الجديد غيّر `MODULE_ID` إلى `<id>`.
3. أضف تعريفه في `public/core/modules.js`:
   ```js
   { id: 'inventory', title: 'المخزون', description: '...', icon: 'fa-boxes-stacked',
     color: '#0ca678', path: '/modules/inventory/index.html' }
   ```
4. كل مجموعات النظام تبدأ بـ `inventory_`.
5. انشر بـ `.\deploy.ps1` ← امنح المستخدمين صلاحية النظام من **المستخدمون والصلاحيات**.

**نقل نظام قديم موجود (ملف HTML مستقل):**
- أضف سكربتات النواة بعد Firebase SDK (انظر القالب).
- احذف `firebase.initializeApp(...)` واستخدم `AllCore.db`، أو
  `AllCore.scopedDb({ oldName: '<id>_oldName' })` لإعادة توجيه أسماء المجموعات بدون تعديل بقية الكود.
- استبدل شاشة الدخول الخاصة به بـ `AllCore.guard('<id>').then(profile => { ...ابدأ النظام... })`.
- استبدل الخروج بـ `AllCore.logout()` وزر الرئيسية بـ `AllCore.home()`.

## ما الذي تغيّر في الأنظمة المنسوخة

تم الإبقاء على كل الشاشات والمنطق كما هي، والتعديلات فقط:

- **الكل:** الاتصال بقاعدة البيانات الجديدة عبر النواة، وإلغاء شاشات الدخول الخاصة
  (الدخول موحّد)، والخروج والرئيسية يعودان للواجهة الموحّدة.
- **الرواتب:** احتساب المسيّر كان يتم على خادم Google Apps Script، فنُقل منطقه حرفياً
  ليعمل في المتصفح على بيانات Firestore. حفظ المسيّر عند الترحيل يُخزَّن في `payroll_sheets`
  بدل Google Sheets. إعدادات المنشأة والأشهر المُرحّلة صارت تُحفظ في السحابة، فتظهر على كل الأجهزة.
- **الوثائق والمهام:** كان يعتمد كلياً على Google Apps Script، فصار يعمل على Firestore بنفس الواجهة.
  أنواع الوثائق تُحفظ في السحابة، والمهام المنجزة تُؤرشف بدل حذفها نهائياً.
- **الخزينة:** الربط مع Google Sheets القديم **معطّل** حتى لا تُكتب بيانات النظام الجديد
  في ملفات الأنظمة القديمة (تصدير Excel يعمل كما هو).

## برنامج التنبيه (ويندوز)

```
tools/notifier/
  notifier.py           يقرأ docs_documents و docs_tasks ويُظهر إشعارات + زر واتساب
  config.example.json   انسخه إلى config.json وعبّئه (لا يُرفع إلى git)
  start_notifier.bat / stop_notifier.bat
```
أنشئ له مستخدماً خاصاً في النظام بصلاحية "الوثائق والمهام" فقط.
